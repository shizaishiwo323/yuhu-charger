# 数据与统计口径

## 四种状态

| 状态 | 页面颜色 | 说明 |
|---|---|---|
| 空闲 | 绿 | 插座可用（不一定没有车停着，只代表这个口没在供电） |
| 充电中 | 红（逐渐灌绿） | 正在充电 |
| 浮充 | 蓝 | 快充满了，小电流补电，仍然占着口；通常一两个小时内会变空闲。和“充电中”算同一次充电 |
| 故障 | 紫 | 其他情况 |

> 一开始我把“浮充”误当成了故障，导致那段时间“充电中 → 浮充”被记成了“充完离开”。
> 教训：**原始快照一定要留着**，规则改了可以重新归类。

## 充电记录的区间表示

每分钟巡查一次，所以一次充电的开始和结束都只知道一个区间：

- 真实开始 ∈ (`start_lo`, `start`]：上一次看到这个口空闲 ~ 这一次看到它在充
- 真实结束 ∈ (`end_lo`, `end`]：上一次看到它在充 ~ 这一次看到它空了

时长取两端中点之差，误差 = 两个区间宽度之和的一半。正常情况下误差在 1 分钟左右。

## 需要单独处理的记录

| 标记 | 含义 | 统计时 |
|---|---|---|
| `approx = 1` | 监控刚启动时就已经在充，开始时间未知 | 时长统计剔除 |
| `forced = 1` | 被 0 点断电强制结束，时长被截断（“至少充了这么久”） | 做时长分布时按**右删失**处理（生存分析） |
| `gap = 1` | 监控断线（两次成功巡查间隔过长）期间开始或结束 | 时长不可信，剔除；次数仍可用 |

另外，监控断线时如果跨过了 0 点，前后都显示“在充”的口其实是两单：前一单在 0:00 被切断，后一单是早上 6 点以后新开始的，需要拆开。

## 占用率

供电时段只有 6:00–24:00，所以占用率也只按这个时段算，否则夜里一大片“空闲”会把占用率拉低。

## 以后想做的

- **到达成功率**：给定“我 T 分钟后到”，在历史快照里找同时段、同主控器、空位数相同的时刻，统计 T 分钟后仍有空位的比例；
  数据不够时用排队模型兜底（该时段新车到达率 + 在充车辆的剩余时长分布）
